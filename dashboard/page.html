Usage and audience

Two imperfect signals. GitHub stars measure developer attention, and GitHub gives only today's total, not when each star was given. npm downloads measure installs through npm only: native installers, Homebrew and release binaries are missed, and CI pipelines count on every run. Compare each repository's trend over time with more confidence than the levels across repositories.

npm downloads per day

Downloads of each CLI's npm package on the median day of each month. The median ignores days npm did not report and automated download storms, such as Codex's in early May 2026.

Where the data comes from

  • Every issue and PR of anthropics/claude-code, openai/codex and anomalyco/opencode, read with gh from the GitHub GraphQL API: number, title, created and closed dates, state, close reason, labels, author type and, for PRs, merge date, who merged it and the issues it closes.
  • GitHub releases of the three repositories, and Claude Code's CHANGELOG.md with each version's npm publish date.
  • Counts of open issues without comments, and the most-reacted open issues, from the GitHub search API.

How each metric is computed

  • Open at month end: issues created before the month ended and not closed by then. A reopened issue counts with its latest close.
  • Days to close: from creation to the latest close. Medians are taken by month of closing.
  • Close reason: GitHub's stateReason. "Closes by automation" carry stale or autoclose (Claude Code) or pending close (OpenCode). Codex does not close inactive issues.
  • Bugs: in Claude Code and Codex, the bug label or a "[BUG]"/"bug:" title. OpenCode does not label issue types, so its bugs are estimated from title wording (error, crash, fails, not working…). Checked against the labels of the other two repositories, that rule is right most of the time but not always: read it as an order of magnitude.
  • Fixes: Claude Code's source is not public, so its CHANGELOG "Fixed" entries are counted. For Codex and OpenCode, merged PRs whose title starts with "fix". Codex PRs are synced from an internal repository with descriptive titles that rarely say "fix", so its count is a floor.
  • Outside contributions: PRs whose author is not on the team and is not a bot or Codex's copyberry account. The team is everyone who has merged a PR (which needs write access) plus anyone GitHub marks as member, collaborator or owner. Many employees hide their org membership and show up as plain contributors, so the role alone overstated outside work.
  • Who can open PRs: a repository setting, read on every run. Where it is "collaborators only", outsiders cannot open PRs at all, so outside contributions there come from before the change; the Outside contributions card names those repositories.
  • Open PRs and merge rate: a PR is open at a date if it was created before it and not yet merged or closed. The merge rate is merged PRs over all PRs closed in the month (merged or not).
  • Usage: GitHub stars are today's count, since GitHub does not list when each star was given; every run of scripts/run.sh records the count, so stars gained per period become measurable over time. npm downloads are the daily counts of @anthropic-ai/claude-code, @openai/codex and opencode-ai; each period uses its median day, which leaves out days npm reported as zero (its stats outages and the latest days) and automated download storms.
  • Versions: GitHub releases for Codex and OpenCode. Claude Code publishes to npm and its GitHub releases only start in Dec 2025, so its CHANGELOG versions are counted with their npm dates.

Limits

  • Time to first response and who closed each issue are not measured: both need each issue's timeline.
  • A "completed" close is not always a code fix; it is also used when a question is answered.
  • Teams often hide org membership, so the share of issues opened by maintainers is a floor.
